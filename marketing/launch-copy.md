## 30-second introduction

AIM Flow is the execution layer we are building for prepared development tasks. It starts by understanding the repository, connects the task to the project and provides an explicit path to a bounded check. The beta is deliberately narrow: the source-check path has been verified in an isolated test environment, while broader build and test support remains work ahead. The point is to learn from a useful task in a real project, with inspectable evidence.

## Claims to preserve

- Always show Beta or technical preview near the product name or download.
- Keep future autonomous delivery separate from current capabilities.
- Say project discovery and configuration proposals, not universal automatic installation.
- Model dispatch is a separate, explicitly approved action.
- Do not present the pipeline illustration as an actual run or dashboard.
- Do not invent customer counts, time savings, success rates, security guarantees or testimonials.
- Source-check evidence is not proof of a complete build, browser qualification or product acceptance.
