# Contributing to AIM Flow Beta

Start with a small issue that describes the project shape, expected behavior and reproducible non-sensitive evidence. Never post keys, private source, personal data or operator journals.

Changes to an execution path need a bounded contract, refusal tests, permission/recovery semantics and truthful evidence boundaries. Preserve unknown outcomes and budget continuity. Do not equate a passing source check with a build, deployment or acceptance.

The initial extraction preserves upstream controller files byte for byte. Proposed engine changes should deliberately update their provenance and tests rather than silently rewriting their hashes. Use the tests listed in `docs/VERIFICATION.md`.

No contribution agreement or additional rights grant is implied by this document. Follow the repository's chosen distribution terms.
