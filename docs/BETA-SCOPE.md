# AIM Flow 0.1.0-beta.8 scope

## Available paths

1. Read-only project discovery and adaptation from committed files.
2. Project-aware installation with a frozen, hashed project receipt.
3. Explicit schema 3 `npm-source-check` planning and reviewed execution.
4. Project-bound intake preview, including a proposal-only profile before build selection. Actual OpenAI dispatch requires a separate project grant, consent and retained shared budget history. Preparing an unvalidated private candidate requires an independently reviewed retained intake and new exact consent. Proposal-only profiles still cannot attach validation or execute project code.
5. A reviewed npm/Vite offline-build route with prior evidence for one pilot project and pinned environment.

6. Preview or separately authorize preparation of an isolated private candidate. Preparation clones the pinned local commit without hardlinks and applies only the reviewed proposal there. It does not change the original checkout, call a model, run project code, push or open a pull request. Resume reconciles the same effect; withdrawal blocks later resume without deleting the candidate.

7. Explicit Sol/xhigh Responses API patch proposals through installed `aim-flow.py deliver-api`, with exact preview authorization, retained historical liabilities and terminal evidence. This advanced path requires an established budget history, produces a separate proposal format and does not apply changes or activate all AIM roles.

These paths have different prerequisites and evidence. Their presence is not a general readiness or execution guarantee.

## Source-check contract

- One explicitly selected existing npm script.
- Explicitly selected committed source files with measured sizes, modes and hashes. There is no fixed product file-count or total-source-byte ceiling.
- Exact committed root `package.json` and `package-lock.json`; no npm workspaces.
- Pinned Node/npm runtime, no dependency installation, no application build/artifacts.
- Selected pre/post hooks are rejected, not silently skipped.
- No services, browser runtime, network dependency or generated input.
- Trusted, reviewed source code and separate bound preparation/execution consent.

`source-check-passed` means the selected check passed. It does not mean the application was built, browser-tested, deployed, security-certified or accepted by its product owner.

## Explicitly outside this beta claim

- Universal execution across frameworks or repositories.
- Automatically granting access or carrying existing project permissions into a new project.
- Multi-user identity, reviewer governance or enterprise compliance guarantees.
- Qualified isolation for hostile code or independently proven CPU/memory/process enforcement.
- A controller-independent watchdog. Interrupted/unknown operations must be reconciled from their original evidence, never blindly replayed.
- Strict denial of container-internal loopback, which remains available in the qualified runtime.
- Reusable issue-to-production delivery for arbitrary external projects.

Legacy project-specific delivery routes are excluded from this distribution. No new repository is granted merge or deployment authority. Customer-specific qualification is separate from this release.

## Pilot fit

A responsible operator, a trusted project, an explicitly reviewed source set and one useful existing source-only check are a good starting point. Projects requiring dependency installation, services, browser tests or builds need a separately reviewed path and qualification.

## Size and resources

Fixed source-file, request-byte, patch-size/count and default changed-line caps are removed. Discovery reads complete committed definitions and repository inventories. New whole-build plans pin a measured source inventory; older inventory-less plans retain their compatibility envelope.

This does not mean unlimited computer or model capacity. Actual provider constraints, approved money/call limits, per-run artifact/resource budgets and untrusted archive/protocol defenses still apply. The intake commands accept an explicit output allowance, bound to the exact request, grant and consent. Token preflight must fit the approved reservation before generation. Preview estimates cannot authorize or increase spending.

The former formatter file-size guard was also removed. Its sandbox, protected inputs and deadline remain, but independent formatter disk-space enforcement is unqualified. Use trusted, reviewed projects. See [project size handling](aim-ci-size-handling.md) for the exact boundaries.
