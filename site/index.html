In the current beta

  • Read-only project discovery and configuration proposals.
  • Project-bound intake preview, with separately approved model dispatch.
  • Sol/xhigh API patch proposals with pinned requests, shared budget history and retained outcomes.
  • Source-cited onboarding and a separate project instance, with optional approved Sol analysis.
  • Reviewed offline npm build/test sequences; one real frontend/backend aggregate qualified in an isolated Linux runtime.

The direction ahead

  • More project-specific build/test and platform qualifications.
  • More real-project integrations and qualification.
  • Progress toward autonomous delivery with AIM roles and quality guidance.

These are development directions, not current capabilities or delivery commitments.

KNOW THE LIMITS

The beta does not establish arbitrary-project end-to-end delivery, complete browser or test qualification, or multi-user governance. A passed source check is not product acceptance.

The method and the engine

AIM sets the method.
Flow moves the work.

The ambition is to carry prepared stories through an agentic delivery process, with project context, development and review working together.

The beta is a focused step toward that ambition. It does not claim to implement the entire AIM method.
